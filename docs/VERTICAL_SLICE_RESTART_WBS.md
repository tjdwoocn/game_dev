# 세로 슬라이스 재시작 WBS

작성: Codex · 검토/승인: Claude Code(프로젝트 리드), PM  
기준일: 2026-08-27  
상태: **리드 검토 대기 — 시스템/비주얼 분업 기준안**

---

## 1. 재시작 목표

현재 프로토타입은 기본 공격·회전베기·돌진과 여러 기반 시스템이 동작하지만,
플레이어가 보는 결과는 행동별 애니메이션·VFX·사운드·캐릭터성이 분리되지 않아
상용 액션 RPG의 세로 슬라이스로 읽히지 않는다.

이번 재시작은 콘텐츠 수를 늘리는 작업이 아니다. **5~10분짜리 한 구간을 처음부터 끝까지
상용 게임의 제작 순서로 완성**하는 작업이다.

### 제안 기준 게임

- 단일 플레이 레퍼런스: **Minecraft Dungeons의 첫 임무형 흐름**
- 가져올 것: 카메라·화면 점유율·공격 박자·적 실루엣 계층·전투 밀도·드랍/획득 흐름
- 가져오지 않을 것: 이름, 설정, 모델, 텍스처, 음원, 맵, UI 원화, 소스코드, 원본 데이터
- 최종 세계관/미술: `docs/content/world.md`, `docs/content/art-direction.md`의 독자 설정

리드가 다른 단일 게임을 선택할 수 있지만, 구현 중 레퍼런스를 여러 게임으로 늘리지 않는다.

## 2. 플레이어-facing 계약

### 한 문장 약속

> 등불지기와 철위병이 무너진 갱도를 돌파하며, 적의 위협을 피하거나 브레이크로 끊고
> 전리품을 챙겨 잠식된 갱도감독관을 쓰러뜨린 뒤 마을로 돌아온다.

### 목표 감정

- 밝고 친근한 셀 셰이딩 외형
- 빠르고 명확한 핵앤슬래시 전투
- 기본 공격으로 자원을 만들고, 회전베기와 돌진을 상황에 맞게 쓰는 작은 전술성
- 보스 예고가 단순 회피 신호가 아니라 브레이크 기회로도 읽히는 긴장

### 핵심 루프 계약

```text
플레이어는 이동·기본 공격·회전베기·돌진으로 무리를 돌파한다
→ 적의 밀도와 예고 공격이 압박한다
→ 처치·레벨업·전리품으로 즉시 강해진다
→ 정예와 보스에서 배운 선택을 조합한다
→ 보상 획득 후 마을로 귀환해 한 판을 닫는다.
```

### 범위

| 범주 | 이번 슬라이스 |
|---|---|
| 거점 | 등불 마을 1개, 문지기와 귀환만 |
| 던전 | 무너진 갱도 1개, 연속 교전 3회 + 보스방 |
| 플레이어 | 등불지기 1명 |
| 동료 | 철위병 1명, 최대 3인 구조는 유지만 |
| 행동 | 이동, 기본 공격, 회전베기, 돌진 |
| 적 | 뼈 병사, 뼈 사수, 돌격형 1종 |
| 정예 | 위 3종 중 1종에 정예 수식어 |
| 보스 | 잠식된 갱도감독관 1종 |
| 아이템 | 무기 2, 방어구 2, 반지 2 |
| 결과 | 보스 보상, 마을 귀환, 재도전 |

### 동결

- 나머지 7개 존 고도화
- 신규 NPC 기능
- 신규 직업과 파티 직접 지휘
- 스킬 트리와 추가 스킬
- 길드·노점·전직·MMO 기능
- 범용 DSL과 미래 콘텐츠용 계약 확장
- 세로 슬라이스와 무관한 패널·미니맵 확대

기존 구현은 삭제하지 않는다. 슬라이스에서 보이지 않게 두고 작업 대상으로 삼지 않는다.

## 3. 완료 판정

다음 항목이 모두 충족되어야 세로 슬라이스 완료다.

- [ ] 마을 → 갱도 → 교전 3회 → 정예 → 보스 → 보상 → 마을 귀환을 실제 입력으로 완주한다.
- [ ] 입력 후 100ms 안에 자세·이동·예고 등 첫 시각 반응이 시작된다.
- [ ] 기본 공격·회전베기·돌진이 실루엣, 타이밍, VFX, 사운드, 카메라 반응으로 구분된다.
- [ ] 적 3종과 보스가 색을 제거한 실루엣만으로 구분된다.
- [ ] 공격·피격·처치·획득·브레이크·레벨업 이벤트에 동기화된 피드백이 있다.
- [ ] 첫 30초 안에 공격 대상/위치/스킬 보존 중 하나의 선택이 발생한다.
- [ ] 보스전에서 회피와 브레이크 선택이 모두 실제로 유효하다.
- [ ] 최대 전투 밀도에서 데스크톱 중앙값 16.7ms 부근을 유지하고 심각한 장시간 프레임 저하가 없다.
- [ ] 활성 플레이 영상과 핵심 프레임 캡처로 밋밋한 구간이 없음을 리드가 판정한다.
- [ ] 타입체크·단위 테스트·세로 슬라이스 플레이테스트가 순차 실행으로 통과한다.

테스트 개수는 완료 지표가 아니다. **실제 입력 녹화에서 한 행동이 완제품으로 보이는가**가 1차 지표다.

## 4. 역할과 경계

### Claude Code — 시스템·게임플레이 리드

- 텍스트 RPG 코어와 전투 규칙의 단일 진실
- 플레이어 행동, 판정, 피해, 자원, 쿨다운, 브레이크
- 적 AI, 보스 패턴, 진행, 드랍, 장착, 레벨업과 밸런스
- 실제 런타임 통합 순서와 시스템 테스트
- 표현 계층이 소비할 읽기 전용 상태와 의미 이벤트 발행

### Codex — 비주얼·테크니컬 아트 리드

- 캐릭터·동료·적·정예·보스 콘셉트와 실루엣
- 모델 소싱/생성, 정리, 리깅, 애니메이션과 소켓
- 맵 아트, 프롭, 재질, 조명, 카메라의 시각적 가독성
- HUD의 시각 구조, 아이콘, VFX와 화면 피드백
- 에셋 매니페스트, 렌더 예산, 시각 QA 자료

### 강제 경계

- Codex 표현 코드는 HP·피해·분노·쿨다운·충돌·AI를 변경하지 않는다.
- Claude 시스템 코드는 색상·모델 경로·VFX 파라미터·HUD 배치를 하드코딩하지 않는다.
- Claude가 `GameplaySnapshot`과 `VisualEvent`를 발행하고 Codex가 구독한다.
- 모델/애니메이션은 `AssetManifest`로 연결하며 런타임 로직은 파일명을 직접 추측하지 않는다.
- 공유 계약 변경은 리드 승인 후 한 사람이 먼저 완료하고 반대편이 소비한다.

## 5. WBS

### WP0 — 안전 기준선과 운영 규칙

담당: PM + Claude Code 리드

- [ ] PM이 현재 전체 상태를 최초 커밋으로 보존한다.
- [ ] 작업 브랜치/작업 위치를 확정한다.
- [ ] `docs/BOARD.md`의 현재 상태 표를 해결/대기 기준으로 정리한다.
- [ ] 동시 WIP를 **플레이어-facing 기능 1개**로 제한한다.
- [ ] 테스트 서버와 브라우저 플레이테스트는 항상 한 번에 하나만 실행한다.

완료 조건: 되돌릴 수 있는 기준점과 현재 작업 하나가 명확하다.

### WP1 — 레퍼런스 잠금

담당: Codex 조사/시각 분석 · Claude Code 리드 검토 · 승인: PM

- [ ] 기준 게임의 5~10분 구간 하나를 고른다.
- [ ] 카메라, 기본 공격, 광역기, 이동기, 일반 몹, 정예, 보스, 드랍 장면을 캡처한다.
- [ ] 각 장면에서 타이밍·화면 점유율·색/실루엣·피드백 층을 표로 만든다.
- [ ] 모방 가능 요소와 독자 제작 요소를 구분한다.
- [ ] 이후 레퍼런스 추가는 리드 승인 사항으로 제한한다.

완료 조건: 팀이 같은 영상·같은 프레임을 품질 기준으로 본다.

### WP2 — 텍스트 RPG 코어

담당: Claude Code · 명세/독립 검증: Codex

- [ ] 플레이어/동료/적/정예/보스 상태 계약
- [ ] 기본 공격·회전베기·돌진·회피 행동 계약
- [ ] 분노·쿨다운·브레이크·무력화·집중 피해
- [ ] 적 공격과 예고/회피 판정
- [ ] 경험치·레벨업·처치 회복·전리품 장착
- [ ] 갱도 3교전 + 정예 + 보스 시나리오
- [ ] 결정적 시드와 전투 이벤트 로그
- [ ] Codex가 선택 밀도와 로그의 시각화 가능성을 독립 리뷰한다.

완료 조건: 렌더러 없이도 같은 입력+시드가 같은 로그를 내고, 전투가 시작·진행·실패·완주된다.

### WP3 — 런타임 이벤트/행동 상태 연결

담당: Claude Code(이벤트 발행/행동 상태) + Codex(표현 구독/어댑터)

- [ ] 텍스트 코어의 `CombatEvent`를 Three.js 런타임 이벤트 명세로 확정한다.
- [ ] 플레이어 행동 상태를 `anticipation → active → recovery`로 분리한다.
- [ ] VFX·사운드·카메라가 전투 로직을 관측 추론하지 않고 이벤트를 구독하게 한다.
- [ ] 회전베기의 독립 `requestAnimationFrame` 이펙트를 공용 풀링 VFX로 이전한다.
- [ ] 이벤트별 애니메이션/VFX/사운드 소켓을 명시한다.

완료 조건: 피해를 주는 코드와 표현 코드가 한 이벤트 ID/시간축을 공유한다.

### WP4 — 에셋 소싱과 스타일 패밀리

담당: Claude Code 리드 · 기술 검수: Codex · 승인: PM

- [ ] 플레이어·적 3종·보스의 콘셉트 시트를 같은 비율/재질/선으로 만든다.
- [ ] 에셋 출처를 `정식 라이선스 팩 / 직접 제작 / 생성형 2D→3D 하이브리드` 중 결정한다.
- [ ] 외부 생성 API를 쓸 경우 PM 확인 후 자격증명 프로브를 실행한다.
- [ ] 모델별 라이선스, 파일 크기, 삼각형, 머티리얼, 텍스처, 애니메이션을 기록한다.
- [ ] 한 화면에서 KayKit·VRM·다른 저폴리 팩을 무계획하게 혼합하지 않는다.
- [ ] idle/run/basic/whirlwind/dash/hurt/death 및 보스 패턴 클립을 확보한다.

완료 조건: 플레이어와 핵심 적이 임시 프리미티브나 단순 재색칠 모델이 아니다.

### WP5 — 플레이어 전투 키트

작업 순서: 회전베기 → 기본 공격 → 돌진. 한 항목 완료 전 다음 항목 금지.

각 행동 공통 체크리스트:

- [ ] 입력 및 입력 버퍼
- [ ] anticipation/active/recovery 시간축
- [ ] 전용 애니메이션 또는 명확한 포즈 변화
- [ ] 판정과 이동/넉백
- [ ] 전용 시작 VFX
- [ ] 전용 타격 VFX
- [ ] 전용 사운드
- [ ] 카메라/히트스톱/피격 반응
- [ ] HUD 자원·쿨다운 반영
- [ ] 실제 입력 녹화와 프레임 스트립
- [ ] 단위 테스트 1개 + 행동 브라우저 검증 1개

완료 조건: 세 행동을 UI를 보지 않고도 화면과 소리만으로 구분한다.

### WP6 — 일반 몬스터와 정예

담당 패키지는 종류별 end-to-end로 배정한다.

- [ ] 뼈 병사: 접근·근접 압박·피격·사망
- [ ] 뼈 사수: 거리 유지·투사체 예고·피격·사망
- [ ] 돌격형: 준비 자세·진로 예고·돌진·벽/회피 결과
- [ ] 정예: 종류와 직교하는 체력/크기/재질/행동 수식어
- [ ] 역할별 실루엣, 무기, 애니메이션, VFX, 사운드 구분
- [ ] 방 단위 무리 구성과 회복 구간 조정

완료 조건: 첫 조우에서 설명문 없이 적 역할을 예측할 수 있다.

## 5. 권장 일정

에셋을 초기에 확보하고 다른 기능을 동결한다는 전제다.

| 기간 | 목표 |
|---|---|
| 1일차 | WP0~1 승인, 텍스트 코어 리뷰 |
| 2~4일차 | 회전베기 완제품 |
| 5~6일차 | 기본 공격 완제품 |
| 7일차 | 돌진 완제품 |
| 8~10일차 | 몬스터 3종+정예 |
| 11~12일차 | 보스 |
| 13~14일차 | 갱도 흐름·보상·UI |
| 15일차 | 완주 QA와 수정 |

에셋 소싱/리깅이 늦어지면 일정도 그만큼 늦어진다. 조명·포스트프로세싱으로 모델 부재를 대신하지 않는다.

## 6. 협업 규칙

1. Claude Code가 우선순위와 품질 기준을 승인한다.
2. PM은 범위·유료 에셋·외부 API·커밋을 승인한다.
3. 한 기능의 담당자는 로직부터 녹화 검증까지 end-to-end로 책임진다.
4. 공유 코어 파일은 착수 전 `docs/BOARD.md` 또는 `docs/CODEX_BOARD.md`에 예약한다.
5. 구현 반대편이 실제 입력으로 검증한다.
6. 완료 보고는 변경 파일, 플레이어 영향, 검증, 다음 작업 네 항목으로 남긴다.
7. 새 시스템/콘텐츠 제안은 현재 WIP 완료 뒤에만 대기열로 받는다.
