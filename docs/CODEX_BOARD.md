## 1. 작업 원칙

### 목표

현재 목표는 보스 수치나 특정 방의 난이도를 맞추는 것이 아니다. 다음 콘텐츠가 늘어나도
기존 전투 코드를 다시 뜯어고치지 않도록, 맵·몬스터·보스·아이템·성장·마을을 연결할
기본 런타임 구조를 만든다.

### 당장 하지 않는 것

- 보스 HP, 공격력, 브레이크 게이지의 세부 밸런스 조정
- 4인 파티 기준 밸런스 조정
- 3인 직접 지휘형 파티로의 방향 전환
- 어둠의전설의 MMO 기능(노점, 길드, 전직, 데스 페널티 등)
- 마을 NPC의 상점·강화·퀘스트 실제 기능
- 새로운 에셋 제작 또는 콘텐츠 파일의 임의 수정

### 파티 기준

- 현재 활성 파티: 플레이어 1명 + 동료 1명
- 구조상 최대 파티: 3명
- 현재 활성 동료: 탱커 1명
- 추가 동료는 `PARTY_CONFIG`에 등록하고 슬롯을 늘리는 방식으로 확장한다.

## 4. 구현 우선순위

## P0 — 핵앤슬래시 전투 기반

### P0-1. 무리 어그로

#### 문제

Claude Code의 밀도 전환으로 던전의 적 수는 늘었지만, 현재 AI는 적을 개별적으로
인지한다. 플레이어가 한 마리를 건드렸을 때 주변 무리가 함께 반응하지 않으면,
화면에 적이 많아도 핵앤슬래시의 전투 리듬이 생기지 않는다.

#### 제안 계약

기존 `EnemyKind`와 분리해 적 개체에 다음 선택적 정보를 둔다.

```ts
enemy: {
  kind: EnemyKind
  state: AIState
  home: Vec3
  stateSince: number
  packId?: string
  alertedUntil?: number
}
```

스폰 데이터 또는 인카운터 데이터에는 다음 개념을 둘 수 있다.

- `packId`: 같은 무리로 반응할 식별자
- `packAggroRange`: 같은 무리로 끌어들일 거리
- `packAlertDuration`: 무리 어그로가 유지되는 시간
- `leashRange`: 홈 영역을 벗어나지 않는 거리

#### 동작 규칙

1. 플레이어 또는 동료가 무리의 한 적에게 피해를 주거나 인지되면 해당 적을 활성화한다.
2. 같은 `packId`의 살아 있는 적을 한 번에 경계 상태로 만든다.
3. 현재 맵에 `packId`가 없는 레거시 스폰은 임시로 근접 스폰 묶음 또는 인카운터 ID를
   이용하되, 장기적으로는 명시적인 `packId`를 우선한다.
4. 벽을 사이에 둔 적까지 무조건 끌어오지 않는다. 무리 알림에는 거리와 시야 또는
   같은 전투 영역 검사를 적용한다.
5. 알림 받은 적이 다시 주변의 모든 적을 무한히 깨우는 연쇄 반응은 막는다.
6. 리쉬 범위를 유지해 다음 방의 무리가 전부 한 방으로 끌려오지 않게 한다.

#### 완료 조건

- 한 무리의 적 하나를 공격하면 같은 무리의 적들이 일정 시간 안에 전투에 참여한다.
- 벽 너머 또는 다음 방의 무리가 부당하게 끌려오지 않는다.
- 적이 홈 영역을 벗어나면 복귀한다.
- 기존 탱커 우선 타겟 선택과 동료 AI가 유지된다.
- 단위 테스트로 단일 적, 동일 무리, 다른 무리, 벽으로 분리된 무리를 각각 검증한다.
- Claude Code가 한 번의 실제 플레이테스트로 전투 감각과 오인 어그로를 확인한다.

### P0-2. 현재 파티 구조 유지

- `PARTY_CONFIG.activeCompanionRoles`만으로 활성 동료를 결정한다.
- 전투·타겟·HUD는 동료 수를 고정하지 않는다.
- 향후 동료를 하나 더 켜도 `partySystem`과 `selectPartyTarget`을 다시 작성하지 않는다.
- 현재 단계에서는 지원가·타격형 동료를 다시 활성화하지 않는다.

## P1 — 콘텐츠를 연결하는 런타임 계약

### P1-1. 스폰 문자와 몬스터 종류 확장

#### 2026-08-27 계약 확정 1차

- 레이아웃 문자에는 몬스터 종류만 둔다. 정예 여부는 `parseMap(layout, eliteCells)`의
  두 번째 인자로 전달하는 `MapCell[]`에서 지정한다.
- 파싱 결과의 스폰은 선택적 `isElite`를 가지며, 존 런타임이 `spawnEnemy(..., isElite)`로
  엔티티에 전달한다. 따라서 `w→W` 같은 대문자 인코딩은 사용하지 않는다.
- 현재 `EnemyKind`에는 기존 세 종류만 남아 있다. `charger`·`ambusher`·`shield`의
  실제 종류 추가는 행동 계약과 스탯을 함께 연결하는 작업에서 진행한다.

사용 예:

```ts
export const MINE_LAYOUT = [/* 종류만 소문자로 작성 */]
export const MINE_ELITES = [{ col: 14, row: 20 }]
const map = parseMap(MINE_LAYOUT, MINE_ELITES)
```

Claude Code 제안값을 기준으로 다음을 검토한다.

| 문자 | 제안 종류 | 필요한 엔진 |
|---|---|---|
| `c` | 돌진형 | 돌진 예고·경로 판정 |
| `m` | 매복형 | 비활성 대기·근접 진입 |
| `s` | 방패형 | 정면 방어 또는 피해 감소 |
| `e` | 정예형 | 일반 몬스터보다 높은 티어 |

확정 전까지 `parseMap`에 문자를 추가하지 않는다. 먼저 `EnemyKind`, `ModelKind`,
`EnemyDef` 확장과 행동별 최소 계약을 합의한다. 콘텐츠 파일이 새 문자를 사용하기
시작하면 파서·스폰·렌더·AI·테스트를 한 작업 단위로 연결한다.

### P1-2. 보스 패턴 데이터화

현재 `src/content/patterns.ts`에는 기존 slam·charge에 필요한 공통 필드가 있다.
다음 단계에서는 `systems/boss.ts`가 공통 필드를 직접 소비하도록 점진적으로 옮긴다.

공통 필드:

- `telegraph`: 예고 시간
- `shape`: 원형·선형·부채꼴·소환 등 판정 모양
- `active`: 실제 판정 또는 지속 시간
- `damage`: 피해량
- `opensBreakWindow`: 약점 노출 여부
- `cooldown`: 다음 패턴까지의 기본 시간
- `repeatCount`, `repeatInterval`: 연속 패턴
- `parameters`: 보스별 특수 파라미터

소환·페이즈 전환처럼 데이터만으로 표현하기 어려운 행동은 무리한 범용 DSL 대신
`kind`별 코드 핸들러를 유지한다. Claude Code는 이 계약에 맞춰 소환형·브레이크 요구형
보스 데이터를 작성한다.

### P1-3. 드랍 조건과 아이템 카탈로그 연결

`DropRule`은 다음 순서로 실제 드랍에 연결한다.

1. 몬스터가 가진 태그와 현재 존 ID를 드랍 문맥으로 전달한다.
2. 플레이어 레벨·캐릭터 클래스·보스 여부를 함께 전달한다.
3. 조건을 통과한 룰만 확률을 굴린다.
4. 룰의 `itemId`로 아이템 정의를 조회한다.
5. 생성된 `ItemInstance`에 요구 레벨과 사용 가능 클래스 정보를 보존한다.
6. 장착 시 조건을 다시 확인한다.

초기 조건은 다음으로 제한한다.

- `minPlayerLevel`, `maxPlayerLevel`
- `requiredClass`
- `enemyKinds`, `enemyTags`
- `zoneIds` 또는 `mapTags`
- `bossOnly`
- `chance`

조건식 DSL을 지나치게 일반화하지 않는다. 콘텐츠가 실제로 필요로 하는 조건만 추가한다.

### P1-4. 존·씬 런타임

현재 `ZONE_DEFS`는 목록·권장 레벨·인카운터 ID·출구를 정의한다. 실제 구현은 다음
책임을 분리한다.

- `zoneSystem`: 현재 존과 전환 요청 관리
- `sceneLoader`: `MAP_LAYOUTS`에서 레이아웃을 읽고 맵 메시를 교체
- `encounterSpawner`: 존의 일반 몬스터·보스·호위 생성
- `transition`: 마을·일반 맵·보스 맵 이동
- `town`: 전투를 비활성화하고 NPC 표시 훅 제공

첫 구현에서는 한 번에 모든 씬을 만들지 않는다. `town → mine → town` 왕복을 먼저
검증하고, 그다음 일반 맵과 보스 맵 출구를 추가한다.

존 완료 조건:

- `MAP_LAYOUTS`의 레이아웃을 존 ID로 로드할 수 있다.
- 마을에서는 적이 생성되지 않는다.
- 일반 맵과 보스 맵의 생성 규칙이 다르다.
- 플레이어·동료·카메라·HUD가 존 전환 후 정상적으로 초기화된다.
- 이전 존의 적·투사체·드랍이 다음 존에 남지 않는다.

## P2 — 성장 시스템 실제 연결

### P2-1. 레벨업과 스킬 해금

현재 XP 누적과 레벨 상승은 존재하지만, `isSkillUnlocked`가 실제 시전 경로에서
호출되지 않는다. 다음 작업에서 다음 순서로 연결한다.

1. 활성 스킬 목록과 예정 스킬 목록을 분리한다.
2. 플레이어가 사용할 수 있는 스킬을 레벨 또는 `unlockedSkills`로 판정한다.
3. `canCast`에서 자원·쿨다운과 함께 해금 여부를 검사한다.
4. 레벨업 시 새 스킬 해금 피드백을 제공한다.
5. HUD와 입력은 잠긴 스킬을 시전할 수 없다는 상태를 표시한다.
6. guard·execution은 효과 설계가 확정된 후 실제 입력과 판정을 추가한다.

기존 whirlwind·dash는 현재 레벨 1에서 계속 사용할 수 있어야 한다. 신규 스킬을
카탈로그에 먼저 등록하더라도 실제 행동이 붙기 전에는 플레이어에게 사용 가능 상태로
노출하지 않는다.

### P2-2. 장비 제한

아이템 생성과 장착 경로에 다음을 연결한다.

- 최소 레벨 미달 아이템은 장착 불가
- 캐릭터 클래스가 허용 목록에 없으면 장착 불가
- 기존 장비 교체·인벤토리 반환 동작은 유지
- 장착 실패 원인을 HUD에서 확인할 수 있도록 훅을 남김

현재 주인공 클래스의 최종 명칭은 세계관 문서와 맞춰 공동 확정한다. 엔진은 문자열을
직접 비교하는 대신 `CharacterClass` 계약을 사용한다.

## 7. 세로 슬라이스: 히트스톱

### [Codex] 히트스톱 코어 타임스케일

- 변경 파일: `src/core/hitstop.ts`, `src/core/world.ts`, `src/main.ts`,
  `src/systems/combat.ts`, `tests/hitstop.test.ts`
- 계약/콘텐츠 영향: 렌더 루프는 계속 실행하고, `res.time.now`만 짧게 감속한다.
  `res.time.realNow`는 실제 고정 스텝 경과를 유지하므로 사운드·VFX는 렌더/실시간
  이벤트에 맞출 수 있다. `res.hitstop`의 `requestHitstop(state, durationMs, scale)`를
  후속 피드백 시스템의 공통 훅으로 사용한다. 중첩 요청은 더 긴 지속시간과 더 강한
  감속을 유지한다.
- 적용 이벤트: 플레이어 피격 70ms, 일반 플레이어 타격 28ms, 일반 적 처치 40ms,
  보스 처치 90ms. 동료의 자동 타격에는 히트스톱을 걸지 않아 파티 규모가 늘어도
  전투가 상시 느려지지 않는다.
- 검증: `npm run test -- tests/hitstop.test.ts` 3/3 통과, `npm run typecheck` 통과.
- 다음 담당자가 해야 할 일: Claude Code는 공격·피격·처치·브레이크 이벤트의 사운드와
  VFX를 실제 피드백 모듈에 연결한다. 피드백 타이밍은 `res.time.realNow` 또는 이벤트
  발생 시점에 맞추고, 히트스톱 요청을 중복해서 별도 감속시키지 않는다.
