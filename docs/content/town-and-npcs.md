# 등불 마을 — 거점과 NPC 컨셉

작성: Claude Code (콘텐츠 담당) · 기준일 2026-08-25

레이아웃은 `src/content/maps/town.ts` 의 `TOWN_LAYOUT`, NPC 데이터는 같은 파일의
`TOWN_NPCS` 에 있다. 지금은 **기능 없이 컨셉과 위치만** 정의한 상태다.

---

## 마을이 하는 일

마을은 메뉴 화면이 아니라 순환의 축이다.

```
던전 탐험 → 전리품 획득 → 마을 귀환 → 정비·성장 → 다음 던전
```

이 순환이 성립하려면 마을에 **던전에서 얻은 것을 소비할 곳**과 **다음에 갈 곳을 고르는
지점**이 있어야 한다. NPC 구성은 그 두 가지를 채우도록 잡았다 — 소비처가 상인·대장장이·
교관·창고, 진입점이 문지기다.

부수적으로 마을은 존 전환 로직을 검증하기에 가장 좋은 대상이기도 하다. 적이 없으므로
전투 밸런스와 무관하게 전환만 순수하게 확인할 수 있다.

---

## 공간 구성

34 × 24 격자. 외곽은 벽으로 닫혀 있고 내부는 광장과 건물 8채로 이뤄진다.

```
        상단 3채 (rows 2–4)
   ┌──────┬──────┬──────┐
   │ 상인 │ 교관 │등불지기│
   └──────┴──────┴──────┘

   중단 2채 (rows 9–11)
   ┌──────┐        ┌──────┐
   │대장장이│  광장  │창고지기│
   └──────┘   P    └──────┘

   하단 3채 (rows 17–19)
   ┌──────┬──────┬──────┐
   │  —   │기록관│   —  │
   └──────┴──────┴──────┘
```

- **플레이어 시작 지점**: (15, 14) — 광장 한가운데
- **건물 위치**: 상단 cols 3–7 / 13–17 / 23–27 (rows 2–4), 중단 cols 6–10 / 23–27
  (rows 9–11), 하단 cols 3–7 / 13–17 / 23–27 (rows 17–19)
- 건물 8채 중 7채를 NPC가 쓰고 한 채는 비워 뒀다 — 나중에 필요한 기능이 생겼을 때 쓸 자리다.

동선 의도는 단순하다. 시작 지점에서 사방으로 두세 걸음이면 어느 NPC에게든 닿고,
문지기(다음 던전)는 시작 지점 바로 아래에 둬서 "정비하고 바로 나간다"가 짧게 끝난다.

## NPC 7종

모두 `src/content/maps/town.ts` 의 `TOWN_NPCS` 에 좌표·인사말·용도가 들어 있다.
지금은 상호작용 시 인사말 한 줄만 띄우면 충분하고, 기능은 나중에 붙인다.

| 역할 | 이름 | 위치 | 나중에 담당할 기능 |
|---|---|---|---|
| `merchant` | 행상 카일 | (5, 5) | 장비·소모품 구매와 판매. 재고는 플레이어 레벨대에 맞춰 갱신 |
| `trainer` | 교관 베르나 | (15, 5) | 레벨로 해금된 스킬의 습득과 스킬 슬롯 배치 |
| `healer` | 등불지기 세인 | (25, 5) | 체력 회복과 상태 이상 해제. 마을 귀환의 기본 동기 |
| `blacksmith` | 대장장이 호른 | (8, 12) | 장비 강화와 수리. 던전 재료의 소비처 |
| `storage` | 창고지기 미라 | (25, 12) | 인벤토리 20칸을 넘는 전리품 보관 |
| `questgiver` | 기록관 레이든 | (15, 20) | 의뢰 수령과 보상. 반복 플레이에 목적 부여 |
| `gatekeeper` | 문지기 도른 | (15, 16) | 던전 선택과 이동. 존 전환의 진입점 |

`tests/maps.test.ts` 가 전원이 건물 안이 아닌 통행 가능한 바닥에 있고, 플레이어가 시작
지점에서 각 NPC까지 실제로 걸어갈 수 있음을 검증한다.

### 배치 근거

- **상인·교관·등불지기를 상단 한 줄에** 모은 것은 귀환 직후 처리할 일(팔기·배우기·회복)을
  한 동선에 두기 위해서다.
- **대장장이와 창고지기는 중단 좌우로 갈라** 놨다. 둘 다 "가진 것을 정리하는" 역할이라
  붙여 두면 광장이 한쪽으로 쏠린다.
- **기록관은 하단**에 뒀다. 의뢰는 나갈 때 챙기는 것이라 문지기와 가까운 편이 낫다.
- **문지기는 시작 지점 바로 아래(15, 16)** — 마을에서 가장 자주 쓸 지점이므로 가장 가깝다.

## 구현 단계 제안

기능 없이도 마을이 "존재하는" 상태부터 만드는 편이 낫다. 순서는 이렇게 본다.

1. **마을 존 진입** — 적 없는 맵으로 전환되고 이동이 되는 것까지. 존 시스템 검증 겸용
2. **NPC 표시** — 모델과 이름표만. 상호작용 없음
3. **상호작용 스텁** — 접근 후 클릭하면 `greeting` 한 줄. 여기까지가 "컨셉만" 단계의 끝
4. **문지기 먼저 기능화** — 던전 선택 UI. 이게 있어야 순환이 닫힌다
5. **등불지기·창고지기** — 회복과 보관. 구현이 가벼운 것부터
6. **상인·대장장이·교관** — 경제와 성장에 얽혀 있어 아이템·스킬 계약이 확정된 뒤

3단계까지는 존 시스템만 있으면 콘텐츠 쪽에서 채울 수 있다. 4단계부터는 존 전환 API와
아이템·스킬 계약이 필요하므로 그 계약이 확정된 뒤에 붙이는 것이 맞다.
