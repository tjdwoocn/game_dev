데이터는 `src/content/itemCatalog.ts` (아이템 18종)와 `src/content/dropTables.ts`
(드랍 룰 24개)에 있다. 검증은 `tests/itemCatalog.test.ts` 가 한다.

## 두 갈래 드랍을 함께 쓴다

이 프로젝트에는 아이템이 나오는 경로가 둘이고, **둘 다 남긴다.**

| | 절차적 생성 (`content/items.ts`) | 카탈로그 (`itemCatalog.ts`) |
|---|---|---|
| 이름 | 등급 수식어 + 부위명 (자동 조합) | 지어 둔 고유 이름 |
| 출처 | 아무 적이나 확률로 | 드랍 테이블이 정한 곳 |
| 역할 | **루팅의 밀도** | **목표** |
| 확률 | 적 종류별 50% | 일반 3~10% · 보스 30~70% |

핵앤슬래시에서 바닥에 아이템이 계속 떨어지는 감각은 절차적 잡템이 만든다. 하지만
잡템만 있으면 "뭘 위해 이 던전을 도는가"가 없다. 그래서 어디서 나오는지가 정해진
카탈로그 아이템을 위에 얹었다.

Codex 의 `ItemDefinition`·`DropRule` 계약을 그대로 쓰되, 콘텐츠에 필요한 세 필드
(`base`·`tags`·`flavor`)만 `CatalogItem` 으로 확장했다. 계약 파일은 건드리지 않았다.

## 클래스 제한에 대한 판단

계약에는 `warrior`·`ranger`·`mystic` 세 클래스가 있지만 **실제로 플레이 가능한 것은
전사뿐이다.** 그래서 지금은 **모든 아이템을 전사가 쓸 수 있게** 만들었다.

궁수 전용 아이템을 지금 넣으면 영원히 못 쓰는 죽은 드랍이 된다. 플레이어는 그걸
"운이 없다" 로 받아들이지 못하고 "이 게임 드랍이 이상하다" 로 받아들인다.

다만 `allowedClasses` 는 미리 나눠 뒀다 — 대검·망치처럼 무거운 무기는 `warrior` 만,
사슬·갈고리는 `warrior`+`ranger`, 반지와 일부 갑옷은 전 클래스. 궁수·술사가 실제로
플레이 가능해지는 순간 이 구분이 그대로 작동한다.

`tests/itemCatalog.test.ts` 가 "전사가 못 쓰는 아이템이 없는지" 를 매번 확인한다.

## 드랍 설계

### 확률 감각

- **일반 적 3~10%** — 카탈로그 아이템은 가끔 나오는 것이다. 밀도는 잡템이 채운다.
- **보스 30~70%** — 보스를 잡을 이유가 되어야 한다. `bossOnly` 로 호위병이 같은 것을
  떨구지 않게 막았다.

`rollDropRules` 는 룰마다 독립으로 굴리므로 보스 하나가 여러 개를 떨굴 수 있다.
핵앤슬래시 루팅 흐름에는 이쪽이 맞다.

### 배치에 담은 의도 몇 가지

- **등불 인장은 어느 깊이에서든 2% 로 나온다.** 등불지기의 물건이라 특정 구역의
  소유가 아니라는 설정을 드랍에 반영했다.
- **성소의 파쇄 망치는 회랑의 원거리형에게서만 나온다.** 성소를 지키던 쪽이
  들고 있었다는 이야기가 드랍 조건으로 드러난다.
- **최상위 3종(시련의 대검·재를 두른 흉갑·꺼지지 않는 불씨)은 10레벨부터.**
  마지막까지 남겨 둘 목표가 필요하다.

### 검증이 잡아 준 것

작성 중 테스트가 실제 실수를 하나 잡았다. 왕좌·수로 보스 드랍에 레벨 조건을 안 걸어서,
보스를 일찍 잡으면 **착용도 못 하는 아이템이 나오는** 상태였다. 드랍 레벨과 착용 레벨의
차이를 2 이내로 강제하는 검사를 넣어 뒀다.

그 외에 자동으로 확인하는 것들:

- 모든 룰이 실제 존재하는 아이템·존을 가리키는가 (오타로 영영 안 나오는 아이템 방지)
- **어디서도 나오지 않는 아이템이 없는가** (만들어 놓고 연결을 잊는 실수 방지)
- 각 전투 존에서 400회 굴렸을 때 실제로 무언가 나오는가
- 등급이 올라갈수록 같은 부위에서 기본 스탯이 강해지는가

## 아직 연결되지 않은 것

카탈로그와 드랍 테이블은 **데이터로만 존재한다.** 실제 드랍 흐름(`systems/loot.ts`)은
아직 절차적 생성만 쓰고 있다. 연결은 Codex 의 P1-3 작업이며, 필요한 것은
`DropContext` 에 현재 존 ID 와 적 종류를 넘겨 주는 것뿐이다 — 판정 함수
(`rollDropRules`)와 데이터(`DROP_TABLE`)는 양쪽 다 준비돼 있다.

`CatalogItem.base` 를 `ItemInstance` 로 옮기는 변환도 필요하다. 등급별 추가 접사는
기존 `rollItem` 의 규칙(일반 0 / 마법 1 / 희귀 2)을 그대로 쓰면 된다.
