## 1. 무엇을 바꿨고 무엇이 남았나

프로토타입은 디아블로풍 어둠으로 시작했다. 배경이 거의 검정(`0x07070c`)이고 안개가 18~46 으로
바짝 당겨져 있어서, **모델은 이미 3등신 아기자기한 형태인데도 화면에서는 어둡고 칙칙하게만 보였다.**
문제는 모델이 아니라 조명이었다.

| | 상태 | 비고 |

## 2. 확정된 스타일

### 스타일 분류

game-art 결정 트리 기준 **Cel-shaded + Low-poly** 를 택했다.
"Approachable / Casual → Soft feel" 갈래이면서, 3D 애니 룩이므로 셀 셰이딩이 붙는다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 셰이딩 | 툰 3단계 | 단계가 적을수록 만화적. 4단계 이상은 PBR 쪽으로 흐려진다 |
| 그림자 바닥값 | 0.62 | **0 이면 그림자가 새까매져 애써 밝힌 톤이 죽는다** |
| 외곽선 | 있음, 짙은 갈색 `0x3f3129` | 순검정은 딱딱하다. 갈색이 따뜻한 톤과 붙는다 |
| 기본 밝기 | 반구광 | 단방향 광만 쓰면 그림자 쪽이 검게 죽는다 |
| 안개 | 45~130 | 가까우면 "좁고 답답한" 인상이 남는다 |
| 캐릭터 비율 | 3등신 | 현재 KayKit 이 이미 이 비율 |

### 팔레트

`src/content/theme.ts` 가 단일 출처다. 색을 코드에 직접 쓰지 않는다.

- 배경·안개 `0xa8c8d8` — 옅은 하늘색. 배경과 안개는 **항상 같은 색**이어야 지평선이 안 끊긴다
- 하늘광 `0xfff4e0` / 바닥광 `0x9a8570` — 따뜻한 위, 흙빛 아래
- 주광 `0xfff0d4` — 살짝 노란 햇빛
- 플레이어 등불 `0xffd8a0` — 약하게만. 지우면 캐릭터가 배경에 묻힌다

`DARK_THEME` 을 지우지 않고 남겨 뒀다. 비교하거나 특정 존만 어둡게 할 때 쓴다.

## 3. 애니 비율 캐릭터로 더 갈 때

지금 룩은 "밝은 저폴리 카툰"이다. 마비노기·테일즈위버의 **애니 비율**(큰 눈, 세밀한 머리카락,
천 재질)까지 가려면 모델 교체가 필요하다. 조명·셰이딩으로는 넘을 수 없는 선이다.

### 무료

| 리소스 | 라이선스 | 쓸모 |
|---|---|---|
| **VRoid Studio** (pixiv) | 무료 툴 | **애니 캐릭터를 직접 만든다.** 목표에 가장 근접 |
| **@pixiv/three-vrm** | MIT | VRM 을 Three.js 에 로드. MToon 툰셰이더+외곽선 내장 |
| **Quaternius** | CC0 | 밝고 아기자기한 저폴리. 모듈식 조합 |
| **Kenney** | CC0 | 소품·UI. 매우 귀엽다 |
| **Mixamo** | 무료 | 애니메이션. VRM 휴머노이드 리그와 리타게팅 |
| **KayKit** (현재) | CC0 | 캐릭터+던전킷. 지금 톤과 이미 맞는다 |

### 유료

| 리소스 | 대략 가격 | 비고 |
|---|---|---|
| Synty POLYGON 시리즈 | 팩당 $20~60 | 밝은 스타일라이즈드. 양이 많고 일관적. **애니는 아니다** |
| Booth.pm VRM 아바타 | ¥1,000~5,000 | 애니 캐릭터. **라이선스 확인 필수** |
| Unity Asset Store 애니 팩 | 다양 | Unity 이관 시에만 의미 |

> **라이선스 주의.** Booth 계열 VRM 은 상당수가 "아바타 용도" 한정이고 게임 내 사용이나
> 재배포를 금지한다. 무료라고 쓸 수 있는 게 아니다. CC0 가 가장 안전하다.

### 남는 작업

1. 캐릭터 모델 교체 (가장 큼)
2. 몬스터는 VRM 이 안 된다 — VRM 은 휴머노이드 전용이라 별도 조달 필요
3. 블룸·소프트 글로우 포스트프로세싱
4. 야외 존 (초원·하늘) — 밝은 톤은 실외가 있어야 산다
5. UI 팔레트 전환

## 4. 안티패턴 — 우리에게 실제로 걸리는 것

| 하지 말 것 | 대신 |
|---|---|
| **저폴리 KayKit 과 애니 VRM 을 한 화면에 섞기** | 교체는 전부 아니면 전무. 섞이면 둘 다 싸구려로 보인다 |
| 색을 렌더 코드에 직접 쓰기 | `theme.ts` 에만 둔다 |
| 그림자를 검정으로 두기 | 바닥값을 띄운다. 안 그러면 다시 다크해진다 |
| 외곽선 두께를 상수로 박기 | **모델 스케일로 나눈다.** 안 하면 캐릭터가 덩어리가 된다 (실제로 겪었다) |
| 배경만 밝히고 UI 는 다크로 두기 | 지금 이 상태다. 고쳐야 한다 |
| 지형까지 외곽선 잔뜩 | 인스턴스 메시에는 안 들어간다. 그편이 맞다 |

## 6. 존별 분위기

"맵이 전부 똑같아 보인다" 의 실체는 바닥 8개 중 7개가 같은 타일이었고 벽 변주와 등불 밀도도
전 맵 공용이었다는 것이다. 킷 모델은 바닥 2종·벽 3종뿐이라 조각을 늘릴 수는 없지만,
**색조·벽 상태·등불 밀도** 세 축이면 인상은 충분히 갈린다. `ZONE_DRESSING` 이 단일 출처다.

| 존 | 색조 | 벽 상태 | 등불 간격 | 의도 |
|---|---|---|---|---|
| 등불 마을 | 따뜻한 미색 | 온전 | 5 | 유일하게 성한 곳 |
| 무너진 갱도 | 흙빛 호박 | 낡음 | 8 | 사람이 파낸 흙바닥 |
| 무너진 회랑 | 차가운 청회색 | **폐허** | 9 | 가장 많이 무너졌다 |
| 지하 납골당 | 바랜 뼈색 | 낡음 | 11 | 어둡고 조용하다 |
| 갈라진 회랑 | 옅은 하늘색 | **폐허** | 10 | 바깥 빛이 든다 |
| 왕좌의 방 | 금빛 | **온전** | 5 | 무너지지 않고 남았다 |
| 함몰 지하수로 | 청록 | 낡음 | **13** | 등불이 가장 드물다 |
| 시련의 회랑 | 붉은 재 | 낡음 | **4** | 불이 많아 달아 있다 |

**두 가지 제약이 값을 정했다.**

1. **색조는 흰색 근처에서만 움직인다.** 원본 텍스처에 곱해지는 값이라 어둡게 잡으면 탁해지고,
   무엇보다 전리품·적이 배경에 묻힌다. 위험과 보상은 어떤 존에서도 읽혀야 한다.
2. **머티리얼을 복제하지 않는다.** 색조는 `InstancedMesh.setColorAt` 으로 준다.
   존마다 머티리얼을 복제하면 오갈 때마다 리소스가 쌓이는데, 존 전환에 이미 텍스처 누수가
   실측돼 있다(한 바퀴당 +35~48). 이 방식은 새 리소스를 0개 만든다.

바닥·벽 색조를 살짝 어긋나게 둔 것도 의도다. 같은 값이면 공간이 납작해 보인다.

## 5. 엔진 이관 시 참고

지금 판단으로는 웹(Three.js)에서 목표 룩의 상당 부분이 가능하다. 그래도 Unity/Unreal 로
옮긴다면:

- **Unity**: URP + Toon Shader. `UniVRM` 으로 VRM 임포트, `UnityChanToonShaderVer2`(무료)가
  사실상 표준. Synty 팩이 URP 에 바로 붙는다.
- **Unreal**: 셀 셰이딩은 포스트프로세스 머티리얼로 직접 짜는 게 일반적이라 Unity 보다 손이 간다.
  애니 룩 목표라면 Unity 쪽이 길이 넓다.

기준선은 이 문서다. 엔진이 바뀌어도 2절의 결정(3단계 툰, 그림자 바닥값, 갈색 외곽선,
반구광, 3등신)은 그대로 옮긴다.
