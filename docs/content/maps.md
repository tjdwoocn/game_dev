# 맵 콘텐츠 — 콘셉트 · 입출구 · 배치 후보

작성: Claude Code (콘텐츠 담당) · 기준일 2026-08-25

레이아웃 데이터는 `src/content/maps/*.ts` 에 순수 `string[]` 로만 있다.
난이도·연결·스폰 테이블 같은 존 메타데이터는 **의도적으로 코드에 넣지 않았다** — 그 계약은
존/씬 시스템(Codex 소유)이 확정할 몫이고, 확정되면 이 문서의 값을 옮겨 담으면 된다.

레이아웃 문자 규약은 기존 `parseMap` 그대로다: `#` 벽 · `.` 바닥 · `P` 플레이어 시작 ·
`w` 근접형 · `a` 원거리형 · `B` 보스. 좌표는 모두 **격자 (col, row)** 이며,
월드 좌표는 `col * TILE`, `row * TILE` (현재 `TILE = 2`).

검증은 `tests/maps.test.ts` 가 담당한다 — 격자 정합성, 외곽 폐쇄, 스폰 도달 가능성,
NPC 위치 유효성을 자동으로 확인하므로 레이아웃을 수정하면 이 테스트를 돌리면 된다.

## 존 시스템에 연결할 때 필요한 것

레이아웃 자체는 그대로 쓸 수 있고, 다음만 존 계약 쪽에서 채우면 된다.

1. **맵 간 연결** — 위 표의 입구·출구 좌표를 어느 존과 잇는지
2. **보스 유무 표기** — `parseMap` 은 `B` 가 없으면 `bossSpawn` 을 (0,0) 으로 둔다.
   일반 맵에서 그 값을 보스 위치로 착각하지 않도록 존 정의에 명시적 플래그가 필요하다.
3. **몬스터 종류 확장** — 현재 스폰 문자는 `w`(근접), `a`(원거리) 둘뿐이다.
   매복형·돌진형·정예를 배치하려면 `SPAWN_CHARS` 에 문자를 추가해야 하는데,
   `content/map.ts` 는 Codex 영역이라 임의로 늘리지 않았다. 문자만 정해주면
   위 "추가 배치 후보" 좌표에 바로 채워 넣겠다.
4. **난이도 티어** — 위 표의 "난이도 의도"는 권장값이다. 실제 값은 존 시스템이 붙고
   플레이 계측이 가능해진 뒤 정하는 편이 낫다.
